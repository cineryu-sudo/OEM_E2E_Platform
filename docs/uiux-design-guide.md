## 1. 디자인 원칙

1. **결론이 먼저 보여야 합니다.** 화면을 열면 "어디서, 왜 막혔나"를 기술 용어 없이 한 문장으로 먼저 보여줍니다. 3GPP/SMPP 코드는 그 문장의 근거로 뒤에 둡니다.
2. **읽는 순서가 곧 일하는 순서입니다.** 무슨 일이 있었나, 근거, 이렇게 복구합니다. 이 세 단계는 실제 작업 순서이므로 번호를 붙입니다. 순서가 없는 정보에는 번호를 쓰지 않습니다.
3. **색은 상태에만 씁니다.** 빨강은 끊긴 곳, 노랑은 착시·주의, 초록은 정상입니다. 마젠타는 화면에서 지금 눌러야 할 버튼 하나에만 씁니다. 장식용 색, 그라데이션, 글로우는 쓰지 않습니다.
4. **세부 정보는 필요할 때만 보여줍니다.** Hop 세부 항목, 측정값, 식별자 전체, 타임라인은 기본으로 접어 둡니다. 장애 Hop의 세부만 처음부터 펼쳐 둡니다.
5. **위험한 조치는 이유와 함께 막습니다.** 실행할 수 없는 버튼은 숨기지 않고 비활성으로 두며, 이유를 버튼 글자로 보여줍니다(예: "주행 중 잠금", "앞 단계가 끝나면 실행할 수 있습니다").

## 2. 디자인 토큰

`styles.css`의 `:root`에 정의되어 있습니다. 대비는 WCAG 2.1 기준이며, 텍스트로 쓰는 토큰은 모두 4.5:1 이상입니다.

- `--brand`는 화면에서 한 곳에만 씁니다. 체크리스트의 "다음 할 일" 버튼, 또는 증적 팩 모달의 첨부 버튼입니다. 로고는 예외입니다.
- 흰 글자를 올린 `--brand` 대비가 4.5로 기준선에 딱 맞습니다. 마젠타 버튼의 글자는 14px 이상, SemiBold(600) 이상으로 씁니다.
- `--line`은 텍스트 색으로 쓰지 않습니다.

## 4. 컴포넌트

### 4.1 상단 바 (`.top-bar`)
- 검색 하나로 VIN, 012 번호, ICCID, IMSI, 요청 ID를 모두 찾습니다. 하이픈·별표·공백은 무시하고 비교합니다(`handleSearch`).
- 찾으면 대기열에서 그 건을 선택하고 검색창에 마스킹된 VIN을 다시 채웁니다. 못 찾으면 작업 기록을 펼치고 이유를 남깁니다.
- Zero PII 배지는 짧은 문구만 보여주고, 근거 조항은 `title`과 스크린리더용 텍스트로 둡니다.

### 4.2 진단 대기열 (`.queue-bar`, `.queue-item`)
- 각 항목은 상태 점, 케이스 제목(`caseTitle`), OEM 약칭으로 구성합니다.
- 점 색은 상태 배지와 같은 규칙(4.3)을 따릅니다. 선택된 항목에는 `aria-current="true"`를 붙이고 흰 배경으로 띄웁니다.
- 좁은 화면에서는 가로 스크롤로 넘깁니다(`.queue-list`).

### 4.3 케이스 헤더와 상태 배지 (`.case-bar`, `.status-pill`)

| 조건 | 톤 | 문구 |
| :--- | :--- | :--- |
| 복구 완료 (`severity: RESOLVED`) | 초록 | 복구 완료 |
| 주행 중 (`IGN_ON_MOVING`) | 노랑 | 주행 중, 원격 조치 잠김 |
| `severity: CRITICAL` | 빨강 | 원인 확인됨, 복구 필요 |
| 그 밖 (`INFO`, `WARNING`) | 노랑 | 망 정상, 고객 안내로 종결 |

- 이 규칙은 `getCaseTone()` 한 곳에서 정하고, 대기열 점과 배지가 함께 씁니다.
- 메타 정보(OEM, VIN, 분석 구간)는 구분 기호 없이 간격으로만 나눕니다.

### 4.4 신호 노선도 (`.route`, `.stop`) — 이 화면의 시그니처 요소

| 상태 | 핀 | 다음 구간 선 | 상태 글자 |
| :--- | :--- | :--- | :--- |
| 정상 (`GREEN`) | 초록 테두리 원 | 초록 실선 | `--sub` |
| 착시·주의 (`AMBER`) | 노랑 테두리 원 | 노랑 실선 | `--amber` |
| 끊김 (`RED`) | 빨강 채운 원과 흰 ✕ | 빨강 점선 | `--red`, 이름도 빨강 |
| 도달 못함 (`brokenAfterHop` 이후) | 회색 점선 원 | 회색 점선 | "정상 대기, 호출 못 받음" |

- 각 정류장에는 Hop 이름, 상태 한 줄, 소요시간(고정폭, `--dim`)만 보여줍니다.
- 정류장 전체가 버튼입니다(`.stop-toggle`, `aria-expanded`). 누르면 actor와 `detailItems`가 펼쳐집니다(`.stop-detail`).
- 시나리오를 바꾸거나 처음 상태로 되돌리면 빨강 Hop만 펼친 상태로 시작합니다. 복구가 끝나면 모두 접습니다.
- 레일 위의 요약 한 줄(`.rail-total`)에는 전체 소요시간이나 병목 구간을 적습니다.
- 레일 아래 "차량과 회선"에는 VIN, 012 번호, 통신사, 시동, 배터리만 보여줍니다. 전체 식별자는 4.9의 식별자 전체 매핑에 있습니다.

### 4.5 1단계: 무슨 일이 있었나 (`#verdictBox`)
- 구성: 단계 라벨, 헤드라인(`.headline`), 쉬운 설명 1–2문장, L2 전용 기술 판정 한 줄(`.headline-sub.eng`).
- 헤드라인은 책임 구간과 결과를 한 문장으로 씁니다. 복구 후에는 `resolved.headline` 문구로 바꿉니다.

### 4.6 2단계: 근거 (`.evidence-list`, `.caution`)
- 근거는 3개를 기본으로 합니다. 각 항목은 굵은 한 줄, 보조 한 줄, 오른쪽 표준 코드로 구성합니다.
- `tone`에 따라 `is-bad`(빨강 배경), `is-warn`(노랑 배경), `is-ok`(흰 배경)로 표시합니다. 정상 근거도 꼭 하나는 넣어 "어디는 문제가 아닌지"를 보여줍니다.
- 표준 코드는 L2에게만 보입니다(`code.eng`).
- 주의 문구(`.caution`)는 1차 회신 착시처럼 실무자가 잘못 판단하기 쉬운 지점 하나를 짚습니다. 복구 후에는 `illusionWarning`의 복구 결과 문구로 바뀝니다.
- 복구 후에는 맨 앞에 "복구 후 정상 응답을 확인했습니다" 근거가 추가되고, 마지막 타임라인 이벤트의 시스템과 코드가 함께 표시됩니다.
- "측정값 자세히 보기"(L2 전용)는 배터리 반원 게이지, 수신감도 막대, 코어망 패킷 막대 3개를 담습니다. 임계치를 넘으면 카드 테두리와 수치를 빨강으로 표시합니다.

### 4.7 3단계: 복구 체크리스트 (`.todo`)

행 상태 규칙 (`renderRecoveryControls`):

| 상태 | 조건 | 표시 |
| :--- | :--- | :--- |
| 다음 할 일 | 아직 안 했고, 앞 단계를 기다리지 않고, 잠기지 않은 첫 행 | 행 배경 `--brand-bg`, 마젠타 버튼 |
| 대기 | `after`로 지정한 앞 단계가 아직 끝나지 않음 | 버튼 비활성, 설명이 "앞 단계가 끝나면 실행할 수 있습니다."로 바뀜 |
| 잠김 | 잠금 대상 조치(`sgsReset`, `provision`)이고 주행 중 | 버튼 비활성, 글자가 잠금 사유 |
| 완료 | 실행함, 또는 복구 완료 상태에서 잠금 대상 조치 | 초록 체크, 버튼 "완료" 비활성 |
| 그 밖 | 실행 가능하지만 다음 할 일이 아님 | 흰 버튼 |

- 마젠타 버튼은 언제나 하나뿐입니다. 다음 단계가 열리면 마젠타가 그 행으로 옮겨갑니다.
- 버튼 글자는 실행 결과를 그대로 말합니다(예: "초기화 실행", "다시 보내기", "증적 팩 열기"). 끝나면 같은 행이 "완료"로 바뀝니다.
- 증적 단계는 증적 팩 모달에서 "ServiceNow / Jira에 첨부"를 눌렀을 때 완료됩니다. 모달을 열기만 해서는 완료되지 않습니다.
- 원격으로 할 일이 없는 건(고객 안내 종결, 주행 중, L1 권한 밖)은 체크리스트 대신 안내 상자(`.action-note`)에 이유와 다음 행동을 씁니다.
- **안전 문구 (`.guardrail`)**: 실행할 원격 조치가 있을 때만 초록으로 "원격으로 실행해도 안전합니다"를 보여줍니다. 주행 중이면 조치가 없어도 빨강 잠금 문구를 항상 보여줍니다. 고객 안내로 끝나는 건과 복구가 끝난 건에서는 숨깁니다.
- **다른 조치 (`#moreActions`, L2 전용)**: 체크리스트에 없는 조치를 흰 버튼으로 모아 둡니다. 원인과 맞지 않는 조치를 실행하면 상태는 바뀌지 않고, 작업 기록에 "상태 변화 없음"이 남습니다.

### 4.8 고객 안내 문구와 작업 기록
- **고객 안내 문구 (`.script-box`)**: 모든 역할에 보여줍니다. 내용은 시나리오의 `csAgentScript`이고, 복사 버튼이 있습니다.
- **작업 기록 (`#actionLogDetails`)**: 기본으로 접어 두고, 제목 옆에 건수를 표시합니다. 모든 조치는 감사 이벤트(`AUDIT-…`)를 마스킹된 VIN·012와 함께 남깁니다.

### 4.9 상세 기록 (`.records`)
- **식별자 전체 매핑**: 8칸, 2열 그리드입니다. L1에게는 IMSI와 EID를 "비인가 권한(L2 전용)"으로 가립니다.
- **시그널링 타임라인 (L2 전용)**: 시각, 구간, 시스템, 이벤트, 코드 5열입니다. 빨강·노랑 행은 왼쪽에 3px 색 선을 넣고 코드 글자에도 같은 색을 씁니다. 시각은 타임존 선택(KST / UTC / 둘 다)을 따릅니다.

### 4.10 증적 팩 모달 (`#evidenceModal`)
- 흰 창 하나에 머리, 본문(초록 Zero PII 안내와 JSON), 바닥 버튼을 둡니다. 주 버튼은 "ServiceNow / Jira에 첨부" 하나입니다.
- 열면 창으로 포커스가 이동하고 Tab이 창 안에서만 돕니다. ESC나 바깥을 누르면 닫히고, 원래 버튼으로 포커스가 돌아갑니다.
- 파일로 저장할 때 파일명은 증적 팩 ID입니다. 원본 VIN을 파일명에 넣지 않습니다.

## 5. 문구 작성 규칙 (`DASHBOARD_BRIEFS`)

시나리오별 쉬운 말 문구는 `mock-data.js` 끝의 `window.DASHBOARD_BRIEFS`에 둡니다. 기존 시나리오 데이터(`DASHBOARD_SCENARIOS`)는 기술 원천 데이터로 그대로 유지합니다.

```js
SCENARIO_A: {
  caseTitle: "원격시동 타임아웃",            // 대기열·케이스 헤더 제목, 증상 기준
  brokenAfterHop: 4,                          // 선택. 이 Hop 이후는 '도달 못함' 점선
  headline: "차량이 아니라 통신망에서 신호가 멈췄습니다",
  summary: "…",                               // 1–2문장, 원인과 영향
  evidence: [{ tone: "bad" | "warn" | "ok", text, sub, code }],
  caution: "…",                               // 착시 주의 한 문장
  steps: [{ action: "sgsReset" | "wakeup" | "provision" | "evidence", title, desc, l2Only?, after? }],
  note: "…",                                  // steps가 비었을 때 안내
  resolved: { headline, summary }             // 복구 후 문구
}
```

- 케이스 제목은 고객이 겪은 증상으로 씁니다("원격시동 타임아웃"). 원인은 헤드라인에 씁니다.
- 헤드라인은 "무엇이 아니라 무엇에서" 또는 "무엇은 정상이고 무엇에서" 꼴로 책임 구간을 분명히 합니다.
- 근거 문장은 사실을 서술형으로 씁니다("기지국이 차량을 한 번도 호출하지 않았습니다"). 보조 줄에는 장비와 시각을, 코드 칸에는 표준 코드 원문을 둡니다.
- 버튼 글자는 동사로 씁니다. 같은 조치는 어디서나 같은 이름을 씁니다(`ACTIONS` 정의를 따름).
- 오류·안내 문구는 무엇이 안 되는지와 다음에 할 일을 함께 씁니다. 사과하지 않습니다.

## 6. 역할별 화면

역할은 화면에서 고르지 않고 로그인 세션 권한으로 정합니다. 목업에서는 URL로 흉내 냅니다(기본 L2, `?role=l1`이면 L1). L1 세션에서는 `body.role-l1`이 붙고 `.eng` 요소가 모두 숨겨집니다.

| 요소 | L1 콜센터 상담원 | L2 운영 실무자 |
| :--- | :--- | :--- |
| 결론, 쉬운 설명, 근거 문장, 주의 | 보임 | 보임 |
| 기술 판정 한 줄, 근거 코드, 측정값 | 숨김 | 보임 |
| 체크리스트 | `l2Only`가 아닌 단계만 (예: Wake-up 재전송) | 전체 |
| L2 단계만 있는 건 | "L2 권한이 필요한 조치" 안내와 이관 유도 | - |
| 다른 조치, L3 증적 팩, 시그널링 타임라인 | 숨김 | 보임 |
| 고객 안내 문구 | 보임 | 보임 |
| VIN 마스킹 | 앞 5자리와 뒤 4자리 | 앞 7자리와 뒤 4자리 |
| IMSI, EID | 비인가 권한(L2 전용) | 부분 마스킹 |

`?demo=1`이면 브리프 맨 위에 기존과 이 화면의 MTTR 비교 배너가 나옵니다. 운영 화면에서는 숨깁니다.

## 7. 반응형과 접근성

- **900px 이하**: 레일과 브리프를 한 열로 쌓고, 검색창을 상단 바 둘째 줄 전체 폭으로 내립니다. 단계 번호는 라벨 위로 올리고, 체크리스트 버튼은 설명 아래로 내리며, 식별자 그리드는 1열로 바꿉니다. 사용자 표시는 숨깁니다.
- **1100px 이하**: 측정값 게이지를 1열로 바꿉니다.
- 레이아웃 그리드는 `minmax(0, 1fr)`로 잡아, 넓은 표가 있어도 페이지가 가로로 넘치지 않게 합니다. 표는 `.table-wrap` 안에서만 가로 스크롤합니다.
- 모든 버튼에는 보이는 포커스 링(`--navy` 2px)을 둡니다. 노선도 정류장은 `aria-expanded`와 `aria-controls`로 펼침 상태를 알립니다.
- 결론 영역은 `role="status"`와 `aria-live="polite"`, 작업 기록은 `role="log"`로 변화를 읽어 줍니다.
- 색만으로 상태를 전하지 않습니다. 끊김은 ✕와 점선, 도달 못함은 점선 원, 완료는 체크 표시로 모양도 함께 바뀝니다.
- `prefers-reduced-motion`이면 펼침 화살표 회전 같은 전환 효과를 끕니다.
