## 1. ⚠️ 핵심 다의어 및 컨텍스트별 혼동 주의 (Polysemes & Context Mapping Warnings)

도메인 스토리텔링(P1·P2) 분석 결과, OEM·통신사(MNO)·공장/PDI·고객센터·차주가 **동일한 단어를 전혀 다른 시스템 상태나 업무 행위로 사용하고 있어** 심각한 의사소통 오류와 데이터 불일치(Pain Point)를 유발하는 핵심 개념군이 발견되었습니다.

### 1.1 「개통 / 활성화 / 가입」 — 5가지 서로 다른 상태 전이

| 구분 | 도메인 용어 | 주체 (Actor) | 대상 (Work Object) | 실제 도메인 의미 (시스템/업무 상태) | 등장 위치 |
|---|---|---|---|---|---|
| ① 공장 망 개통 | **시험 개통** (Test Provisioning) | OEM 운영팀 → MNO | 012 법인 명의 회선 (ICCID/IMSI) | 공장 라인오프 시점, EOL 통신 검사를 위해 MNO 전산에 012 번호가 부여된 법인 회선을 생성·연결하는 것 `[사실][추정]` | P1 #3 |
| ② 로컬 프로파일 전환 | **로컬 프로파일 다운로드 및 개통** (RSP Activation) | 수입차 PDI 기술팀 → 본사 개통서버 / 국내 MNO | 내장형 eUICC (TCU) | 해외 본사 공장에서 심어진 글로벌 부트스트랩 프로파일을 평택항 PDI에서 국내 MNO 프로파일(SGP.02/SGP.32)로 무선 교체·개통하는 것 `[사실][추정]` | P1 #21, P2 #B5 |
| ③ 서비스 계정 연동 | **커넥티드 서비스 가입** (Service Subscription) | 고객(차주) / 카마스터 → OEM 운영팀(서버) | 고객 계정 + 차량(VIN) + 약관 동의서 | 차량 인도 시점에 차주가 위치정보·개인정보 약관에 동의하고 OEM 앱/계정과 차량(VIN)을 바인딩하여 무상/유상 서비스 권한을 얻는 것 `[사실]` | P1 #5, #15 |
| ④ 망 휴면 해제 | **정식 활성화 (휴면 해제)** (Line Resume / Commercial Activation) | OEM 운영팀 → MNO → 차량 TCU | 012 회선 + 차량 TCU 설정 | 고객의 서비스 가입 직후, 물류/재고 기간 동안 일시정지(휴면)되어 있던 MNO 회선을 깨우고 TCU에 활성화 설정(프로비저닝)을 내려보내는 것 `[추정]` | P1 #6, #24, P2 #B1~#B3 |
| ⑤ B2C 별도 개통 | **차량용 Personal eSIM 개통** (Consumer eSIM Activation) | 고객(차주) → 국내 MNO (SKT 등) | 인포테인먼트용 소비자 eSIM (SGP.22) | 차량 기본 B2B 텔레매틱스 회선과 분리하여, 대용량 5G 미디어 데이터를 쓰기 위해 고객이 직접 본인 명의로 통신사 요금제에 가입·개통하는 것 `[사실]` | P1 #23 |

> **[추론] 아키텍처 주의사항**: MNO가 말하는 "개통일"은 ①(라인오프 시점) 또는 ②(PDI 입항 시점)인 반면, 고객과 딜러가 말하는 "개통/가입일"은 ③·④(인도 후 앱 가입 시점)입니다. 이 시점 차이가 **재고 기간 과금 귀책 실랑이(PP-01)**와 **5년 무료 기간 기산일 민원(PP-02)**의 직접적 원인이 됩니다.

### 1.3 「휴면 / 일시정지 / 물류모드 / 차단 / 해지 / 말소」 — 차량·서비스·회선·행정 상태의 불일치

### 1.4 「정상 발송 / 개통 정상 / 단말 무응답」 — 장애 진단 시 구간별 '정상'의 착시 (P2 심화)

P2 워크숍에서 원격제어 먹통(26시간 핑퐁)과 개통 활성화 Pending(8일 핑퐁)이 발생하는 핵심 원인은 **각 조직이 말하는 '정상'의 범위가 자기 시스템 경계 안으로만 극도로 협소하게 정의**되어 있기 때문입니다.

| 주체 (Actor) | 실무자가 보는 상태/응답 문구 | 실제 기술적 의미 (Fact) | 다른 조직이 오해하는 의미 (착시) | 등장 위치 |
|---|---|---|---|---|
| **OEM 클라우드팀 / 해외 본사 L3** | **"Wake-up SMS 정상 발송 (`Submit_SM_Resp OK` / `Sent`)"** | OEM/본사 서버가 SMS 중계 게이트웨이 또는 국제 SMS Hub로 패킷을 던지고 **큐 접수 응답(ACK)을 받았다**는 뜻 `[추정][가정]` | "차량(TCU)까지 깨우기 신호가 무사히 도착했다 (따라서 우리 서버 책임은 없다)" | P2 #A5, #B5 |
| **MNO B2B 포털 / 1차 장애데스크** | **"회선 상태: 개통 정상 (`사용중`) / 망 특이사항 없음"** | MNO 과금·가입 원장(HLR/HSS)에 `012 번호`가 정지/해지되지 않고 등록되어 있으며 기지국 장비에 전면 장애가 없다는 뜻 `[사실][추정][가정]` | "지금 당장 해당 차량에 무선 신호(Paging)와 데이터 패킷이 정상 소통되고 있다" | P2 #A6, #A8, #B6, #B8 |
| **MNO SMS-C (1차 회신)** | **"단말 무응답 (`Absent Subscriber`)으로 Spooling"** | SMS-C가 착신 시도를 했으나 단말로부터 최종 수신 ACK가 안 와서 재전송 큐에 대기 중이라는 결과 현상 `[추정][가정]` | "차량이 지하주차장(음영)에 있거나 TCU 모뎀이 Deep Sleep 불량으로 죽어 있다" *(실제론 MME SGs 세션 꼬임으로 기지국 Paging조차 안 나간 경우도 동일 코드 발생)* | P2 #A8, #A10, #A12 |
