E2E 진단 화면 개선 시안 3종

세 시안 모두 같은 장애(A사 원격시동 타임아웃, Hop 4 코어망 SGs 꼬임)를 보여줍니다. 무엇을 먼저 보여주는지만 다릅니다.

공통 원칙

  1. 결론을 맨 위에 한 문장으로. “어디서, 왜 막혔나”를 기술 용어 없이 먼저 말하고, 코드는 근거로 내려 보냅니다.
  2. 색은 상태에만. 빨강은 끊긴 곳 하나, 노랑은 착시 구간, 마젠타는 실행 버튼 하나에만 씁니다.
  3. 원인 옆에 조치. 스크롤 없이 첫 화면에서 추천 조치를 바로 실행할 수 있게 합니다.
  4. 세부 정보는 필요할 때. 타임라인, 식별자, 증적은 탭·인스펙터·드로어로 옮깁니다.
  5. 본문은 Pretendard, 코드만 고정폭. 현재 화면의 모노스페이스 남용이 가독성을 가장 많이 떨어뜨립니다.

시안 비교

시안핵심 요소참고한 화면잘 맞는 사용자
A. 경로 뷰
다크		끊어진 5구간 트랙 + 원인/조치 2단 + 하단 탭Linear, Vercel 대시보드 (흐린 사이드바, 진단 대기열)관제 L2, 여러 건을 연달아 처리하는 운영자
B. 트레이스 뷰
라이트		로그 시간축 워터폴 + 오른쪽 인스펙터Datadog, Honeycomb, Dynatrace 트레이스 워터폴코어망·클라우드 엔지니어, L3 분석
C. 진단 브리프
라이트		세로 노선도 + 1-2-3 단계 브리프 + 상담원/엔지니어 보기 전환incident.io, PagerDuty 인시던트 페이지콜센터 L1과 L2가 같은 화면을 쓰는 경우
